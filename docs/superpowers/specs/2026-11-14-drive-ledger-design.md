# C盘每日空间增长监测设计草案

本工具用于查清 C 盘每天多占用的空间去了哪里。以磁盘实际占用变化为总账，提供目录和文件的增长明细，并明确显示无法归因的差额。

## 已确认的需求与当前环境

- 监测对象为当前电脑的 C 盘，用户希望持续了解每天新占用的空间。
- 用户接受开机后常驻后台，并有可用的管理员账户。
- 2026 年 11 月 14 日只读检查结果：C 盘为 NTFS，容量约 371.14 GiB，剩余约 52.12 GiB。D 盘为 NTFS，剩余约 790.5 GiB。剩余空间会随使用变化。

以下采样频率、技术选型和保存期限是建议默认值，供用户审阅。

## 统计口径

### 磁盘实际变化

在两个实际观测时刻之间，空间净增长等于终点（总容量减去空闲字节数）减去起点（总容量减去空闲字节数）。仅当总容量不变时，才等价于起点空闲字节数减去终点空闲字节数。正数表示多占用，负数表示释放。使用整卷空闲空间指标，避免将账户配额指标当成整盘数据。

每天按电脑本地时区归档，同时保存 UTC 时间和时区偏移。当天记录为进行中，首日记录为从安装后首次有效观测开始。跨天时尽量保存边界观测；关机、休眠或采集停止导致边界缺失时，显示真实比较时间和缺口，不把跨越多天的变化均摊到各天。

### 文件和目录变化

主要按文件实际分配空间统计，文件逻辑大小作为补充。对每个文件保存最近一次成功观测的分配空间和身份信息，再记录变化。

- 新文件在成功观测时已经分配的空间，记为新增文件占用。
- 已有文件分配空间增加，记为已有文件增长；减少记为释放。
- 删除文件时使用最后一次已知分配空间计算释放，并保留原路径供查询。
- 同卷移动或重命名记为路径变化。目录之间的归属变化单列为迁移，整盘新增占用为零。

增加项和减少项是有效观测之间累计得到的变化，不代表所有写入字节数，也不能保证捕获极短暂文件的全部占用。若文件在大小读取前就被删除，其空间记为未知，不推测一个大小。

目录增长排行按所选时间段内的净变化排序，并可分别查看增加项和释放项。父目录统计包含子目录，父子目录不能再次相加。硬链接按文件身份在整卷去重，目录归属采用固定规则选出的一个路径，同时展示其他链接，避免重复计算。

磁盘净变化减去同一比较窗口内已归因文件变化，得到尚未归因的有符号差额。权限不足、采集延迟、系统内部占用和未覆盖的数据流等情况都可能形成差额；除非有观测证据，否则不指定其原因。文件归因窗口与磁盘窗口不一致时，标明时间偏差和归因完整性。

## 第一版功能

1. 自动记录 C 盘空闲空间及其每日净变化。
2. 查询最近 365 天中某一天或连续日期的目录增长排行；最近 30 天支持进一步下钻到增长文件。
3. 区分新增文件、已有文件增长、释放空间和目录迁移。
4. 查询历史记录，并导出所选时间范围的 CSV 明细。
5. 显示初始化进度、采集状态、比较时间、访问失败数量和记录缺口。
6. 提供托盘入口、暂停采集、恢复采集和手动核对功能；关闭统计窗口后继续后台采集。

第一版聚焦空间观测和定位。文件清理、追溯安装前的完整历史、定位具体写入进程以及其他磁盘的监测不在本次范围内。

## 实现方案比较

| 方案 | 优点 | 代价与限制 |
| --- | --- | --- |
| 每天扫描并比较清单 | 结构简单，适合比较扫描时仍存在的文件 | 全盘反复扫描，扫描间的短暂占用容易遗漏 |
| 后台追踪变化并定期核对 | 能持续积累记录，适合排查 C 盘日常增长 | 需要处理日志缺口、权限、文件身份和恢复逻辑 |

用户已接受推荐的后台常驻方向。建议采用第二种方案，并保留扫描核对作为恢复和校验手段。

## 后台采集与权限

采用 Windows 服务采集、普通权限托盘程序查看统计的结构。安装或卸载服务时使用管理员提升授权；管理员账户在日常运行时仍可能受到 UAC 限制。

建议使用 C#、受支持的 .NET LTS、WPF 托盘界面和 SQLite 本地数据库。面向当前 Windows x64 电脑提供包含运行时的安装包，实际操作系统版本在开发准备阶段确认。

采集服务以本机系统身份运行。服务的产品功能只读取 C 盘元数据，向自己的数据目录写入统计；不更改被监测文件的权限。界面与服务使用仅限本机的通信通道，将访问限制为安装账户和本机管理员。具体通信协议与日志轮换方式由实现者决定。

建议默认每分钟采样一次整盘空闲空间，每约 5 秒批量读取一次已有的 NTFS USN 变更日志。USN 日志用于发现哪些对象变化，文件大小仍需另外查询。连续写入的文件采用合并刷新，最长约一分钟刷新一次已知大小，避免等到文件停止变化才更新。

首次运行先建立索引，同时保留并追赶扫描期间的日志变化，完成一致性核对后标记基准就绪。初始化期间先积累磁盘空闲空间记录，文件归因标记为未完成。

每天执行一次低优先级元数据核对；错过计划时间时在恢复运行后补做。核对只枚举身份、路径、大小和必要属性，不读取文件内容。扫描支持取消、限速与分批提交；扫描进度不阻塞磁盘空闲空间采样。

启动时校验卷身份、USN 日志标识和消费位置。日志仍连续时追赶变更；日志不存在、已被重建或所需记录已覆盖时，降级为扫描核对并标记缺口。第一版不自动创建、删除或重置系统 USN 日志。识别到 C 盘卷身份变化时建立新基准，保留旧历史而不跨卷比较。

## 数据与边界情况

建议将数据库放在 D 盘的专用目录，避免统计工具的主要索引继续占用 C 盘。安装时显示实际路径；D 盘不可用或写入失败时，停止写入并提示，不静默换到 C 盘。

保存当前文件索引、最近 30 天的文件变化明细和最近 365 天的每日汇总。每日汇总同时保存整盘数据和有变化目录的增加、释放、迁移及净变化，并保留当时的目录路径和层级。第 31 至 365 天可以查询目录排行，文件下钻明确提示超出明细保存期，不尝试用当前文件清单还原旧明细。跨日期目录排行按当时的路径归组。

清理历史不删除当前有效索引。文件身份使用卷身份和包含复用序号的完整文件标识，保留链接与父目录关系，以支持删除后的路径解释。

遇到重解析点时记录其本身，扫描不跟随其目标，避免跨卷、循环和重复统计。稀疏文件、压缩文件及硬链接按实际分配信息和文件身份处理。第一版对无法独立计量的数据流或系统内部占用保留差额。

采集和数据库更新采用有界批次。每个成功批次将文件索引、统计变化及 USN 消费位置一并提交，防止重启后重复计入；恢复扫描发现的差异只归入真实观测窗口，不冒充缺失期间逐日变化。

## 验证与完成标准

开发时首先验证本机能否读取所需元数据，以及首次索引耗时、后台 CPU、内存和数据库大小，再据实调整默认频率。

正式交付前至少验证以下场景：创建和扩展文件、截断和删除文件、同卷移动、硬链接、稀疏或压缩文件、服务重启、USN 缺口、跨午夜及休眠恢复、目录访问失败和数据盘写入失败。

在静止的受控测试目录中，应能正确解释分配空间变化；整盘实测必须同时显示磁盘变化、已归因变化和剩余差额。任何无法准确归属的历史区间都应有可见的完整性标记。

交付物为本机可安装的软件、安装卸载说明和验证结果。当前阶段交付设计草案，实际性能和归因覆盖率由原型及本机验证确定。
